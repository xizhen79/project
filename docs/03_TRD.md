# 현장별 공정·기성 대시보드 — TRD(기술 요구사항 문서)

## 한눈에 보기

- Next.js와 TypeScript로 PC용 4개 화면을 만들고, 디자인 시안의 배치와 분위기를 따릅니다.
- 파일 검사·계산·CSV 생성은 브라우저에서 처리하며, 자료는 새로고침 전까지만 메모리에 둡니다.
- 모든 화면이 같은 필터와 계산 함수를 쓰고, 첫 달의 계산 불가와 정상값 0.0을 구별합니다.
- Gemini `gemini-3.8-flash` 호출과 API 키 보관은 서버에서만 담당합니다.
- Vitest와 브라우저로 로컬 검증 후 멈추며, 무료 구간 내 월 0원을 기준으로 GitHub 저장·Vercel 배포는 각각 별도 요청 후 진행합니다.

## 어떤 구조로 만들지

### 화면과 코드의 역할

아래 위치는 모두 프로젝트 폴더 기준의 **구현 예정 위치 (AI 결정)**입니다. 원본·문서·시안은 기존 위치를 유지합니다.

| 예정 위치·역할 | 담당할 일 | 나누는 이유 |
|---|---|---|
| `app/layout.tsx` | 공통 상단 메뉴와 브라우저 자료 공유 기능을 모든 페이지 바깥에 배치 | 메뉴 이동 때 적용 자료와 필터가 다시 초기화되지 않도록 함 |
| `app/page.tsx` — `/` | 현황 요약: 필터, 큰 숫자 4개, 점검 순위, 월별 추이 | 첫 화면에서 점검할 현장을 찾음 |
| `app/comparison/page.tsx` — `/comparison` | 현장별 비교표와 행 안의 공사기간·상황·대응 기록 | 별도 상세 페이지 없이 숫자와 기록 비교 |
| `app/import/page.tsx` — `/import` | 파일 선택·검사·미리보기·취소·전체 교체 | 적용 중인 자료와 아직 확인 중인 파일을 구별 |
| `app/ask/page.tsx` — `/ask` | 현재 범위·예시 질문·입력·답변·대기·실패 상태 | AI 연결과 기본 조회 기능을 분리 |
| `app/api/ask/route.ts` — `POST /api/ask` | AI 질문을 받는 서버 전용 주소. 요청 검사·키 확인·Gemini 호출·오류 변환 | 브라우저에 키를 보내지 않음. 이 주소는 다섯 번째 화면이 아님 |
| `state/` | 적용 자료·파일 후보·필터·펼친 행·AI 요청 상태 관리 | 화면마다 서로 다른 자료를 보관하는 문제 방지 |
| `components/` | 필터, 지표 카드, 상태 글자, 점검 목록, 차트, 비교표, 기록 패널 등 재사용 | 같은 숫자 표시·필터 동작·상태 표현 유지 |
| `lib/data/` | 원본 15개 필드 정의, CSV/JSON 해석, 입력 검사, 월·현장별 행 찾기 | 잘못된 자료가 계산 단계로 넘어가지 않도록 함 |
| `lib/calculations/` | 범위 선택·가중평균·기성률·당월기성액·순위·월별 요약 계산 | 화면·CSV·AI가 같은 함수를 사용. 화면 없이도 자동 검사 가능 |
| `lib/export/`, `lib/ai-context/` | 같은 조회 결과로 CSV와 AI 근거 묶음 생성 | 내보내기와 AI만 별도 필터를 적용하지 않도록 함 |
| `lib/server/` | 서버 전용 Gemini 연결과 설명 지침 | 화면 코드에서 키나 AI 연결 모듈을 가져오지 못하도록 분리 |
| `styles/` | 공통 색·간격·글자 크기·숫자 정렬과 화면별 스타일 | 시안의 배치와 분위기를 일관되게 적용 |
| `tests/` | Vitest로 계산·검사·상태 변경·AI 서버 응답 처리 확인 | 핵심 동작을 반복 확인하고 오류를 재현 |
| `data/`, `design/`, `docs/` | 원본·시안·확정 문서 보존 | 시안의 예시 수치를 정답이나 실제 실행 결과로 혼동하지 않음 |

### 자료와 화면 상태 관리

| 관리 대상 | 구현 규칙 | 이유·FRD 연결 |
|---|---|---|
| 원본 행 | 15개 필드만 원본 자료로 보관. 금액은 백만원, 계획·실제 공정률은 0~100의 % 수치, 날짜·월·현장 ID는 문자열 | FRD 입력 검사 기준. 기성률·상태 등을 원본에 중복 저장하지 않음 |
| 적용 자료와 파일 후보 | 현재 적용 자료와 검사 중인 파일을 따로 보관. 전체 검사·계산 준비 성공 후 한 번의 상태 변경으로 교체 | F16~F20. 오류·취소·적용 실패 때 기존 자료·필터 유지 |
| 검사 순서 | 파일 해석 → 15개 열·필수값·단위·버전 → 숫자·날짜 → 월+현장 중복 → 현장 고정 정보 → 누적값 감소 → 누락 경고 | FRD 검사 기준을 분리해 오류 행·필드·이유를 표시 |
| CSV 처리 | **(AI 결정)** 자동 숫자 변환을 끄고 빈값·문자 여부부터 검사한 후 숫자로 처리. 따옴표 안 줄바꿈도 보존하고 오류 위치를 원본 파일 행과 연결 | 빈 문자열이 0으로 바뀌는 오류와 기록 손상 방지 |
| 일부 파일 | 144행을 강제하지 않음. 월 누락은 경고하고 실제 집계 현장 수 표시. 내보내기 계산 열은 무시하고 원본 15개 열에서 재계산 | FRD의 일부 자료 허용·계산 열 처리 유지 |
| 파일 읽기 순서 | **(AI 결정)** 파일 선택마다 검사 번호를 새로 만들고 마지막에 선택한 파일의 결과만 적용 후보로 인정 | 먼저 고른 파일의 늦은 검사 결과가 나중 파일을 덮지 않도록 함 |
| 공통 필터 | 월·지역·유형·현장 한 묶음을 공유. 지역·유형 변경 시 현장이 범위 밖이면 전체로 변경. 모든 화면이 한 조회 결과 묶음을 사용 | F03~F10·F21·F24. 필터가 서로 어긋나는 문제 방지 |
| 첫 조회·초기화 | 정상 원본은 2026년 9월·전체. 9월이 없는 일부 파일은 마지막 월·전체. 필터 초기화도 해당 기본값 사용 | F07·F20의 결정 유지 |
| 비교표 상태 | 행 구분값은 월+현장 ID. 여러 행 펼침 가능. 점검 순위 클릭은 필터를 바꾸지 않고 비교표로 이동해 대상 행 강조·펼침·위치 이동 | F12~F15. 기본 조회를 그대로 두고 기록에 접근 |
| 새 범위·새 자료 | 필터 변경·자료 교체 때 강조·펼침과 이전 AI 답변을 제거. 대화 초기화는 입력·답변만 제거 | F07·F20·F25의 초기화 범위 구별 |
| 자료 보관 | 브라우저 메모리(현재 열린 앱이 임시로 보관하는 공간)에만 보관. localStorage·sessionStorage·쿠키·데이터베이스로 자료를 저장하지 않음 | F02. 페이지 이동은 유지하지만 새로고침하면 파일을 다시 가져옴 |
| 데이터 파일 배포 경계 | 업로드 파일 전체를 서버에 보내거나 `public/`에 복사하지 않음. GitHub에는 비밀값을 제외한 코드·문서와 교육용 원본만 저장 대상으로 검토 | 파일 읽기는 브라우저 담당. 원본은 교육용이며 실제 현장 자료를 수집·보관하는 기능 없음 |

### 계산과 표시 구조

| 항목 | 구현할 규칙 | 예시·이유 |
|---|---|---|
| 계산 함수 | 입력 자료와 필터를 받아 결과만 반환하는 함수로 작성. 화면·CSV·AI에서 별도 산식을 만들지 않음 | 같은 9월 전체는 어디서나 기성률 67.2% |
| 원본·계산·표시 구별 | **(AI 결정)** 숫자 검증 후 decimal.js로 계산. 내부 정밀도는 유효숫자 40자리로 설정하고 소수 첫째 자리 반올림은 표시 단계에서만 수행. 표시에는 일반 반올림 사용 | 임의로 중간 소수 자릿수를 잘라 계산하지 않음. 2025년 12월 차이는 표시된 27.0−26.9가 아닌 계산 결과 0.2pp |
| 현재 지표 | 선택 월의 같은 범위 계약금액·누적기성액 합계로 기성률, 계약금액 비중으로 계획·실제 공정률 계산 | 9월 계약 630,700·누적 424,063.4백만원, 기성률 67.2%, 계획 73.2%·실제 71.2% |

| GitHub | `.env.local` 등 비밀 환경 파일은 `.gitignore`로 제외하고 업로드 대상에 비밀값이 없는지 확인 | [Google 키 보안 지침](https://ai.google.dev/gemini-api/docs/api-key)에 맞춰 서버에서 호출하고 저장소에 키를 남기지 않음 |
| 배포 서버 | Vercel의 해당 환경 변수에 별도 등록. 로컬 파일을 업로드하는 방식으로 공유하지 않음 | 로컬·미리보기·운영 환경의 키 설정을 구별 |
| 오류·기록 | 키 값과 인증 헤더를 응답·화면·로그에 남기지 않음 | 오류를 확인하는 과정에서도 비밀값 보호 |
