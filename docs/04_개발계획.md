# 현장별 공정·기성 대시보드 — 개발 계획

## 한눈에 보기

- EPIC(큰 작업 묶음) 3개, Story(사용자가 할 수 있는 작은 작업) 13개를 순서대로 만듭니다.
- E1에서 자료 가져오기·필터·현황·추이, E2에서 점검·기록·CSV, E3에서 AI 설명·로컬 전체 검증을 진행합니다.
- Story마다 브라우저에서 해 볼 행동과 보여야 할 결과를 기준으로 확인합니다.
- EPIC 하나씩 구현·자동 검사·브라우저 확인을 진행하고, 사용자 확인 후 다음 EPIC으로 넘어갑니다.
- 로컬 전체 검증 후 결과를 보고하고 대기하며, GitHub 저장과 Vercel 배포는 각각 별도 요청 후 진행합니다.

## Story 표

### E1 — 자료 가져오기·필터·현황·추이

| 번호 | 사용자가 할 수 있는 일 | 확인할 행동 | 보여야 할 결과 |
|---|---|---|---|
| S01 | 파일을 검사하고 미리보기 | 처음 앱을 연 뒤 자료 가져오기에서 정상 CSV 선택 | 처음에는 자료 없음. 선택 후 **144행·15개 원본 열**, 앞 5행 미리보기와 검사 결과 표시. 적용 전 자료는 바뀌지 않음 |
| S02 | 자료를 전체 교체하거나 취소 | CSV 적용 후 같은 JSON 적용. 이어서 새 파일 미리보기 취소, 오류 파일 3종 각각 선택 | 정상 교체 후에도 **144행**. 취소·오류 시 기존 자료 유지. 오류 행·항목·이유와 적용 불가 안내 |
| S03 | 필터로 현황 숫자 확인 | 9월 전체 → 인천·공동주택 → 경기·D 선택 후 지역을 인천으로 변경 → 필터 초기화 | 9월 전체 기성률 **67.2%**·계획 **73.2%**·실제 **71.2%**·차이 **−2.0pp**. 인천·공동주택은 A·G와 기성률 **61.2%**. 범위 밖 D는 전체 현장으로 변경. 초기화는 9월 전체 |
| S04 | 계획·실제 공정률 추이 확인 | 9월 전체 차트의 월별 점에 마우스를 올리고, D 선택 후 8·9월 확인. 기준 월을 8월로 변경 | 전체는 12개월의 계획·실제 선과 월별 안내. D는 **−11.2pp → −10.7pp**. 8월 선택 시 9월은 표시하지 않음 |
| S05 | 당월기성액과 누적액 구별 | 9월 전체의 금액·막대 확인 → 2025년 10월 선택 → J·2026년 7월 선택 | 9월 누적 **424,063.4**, 당월 **28,878.7백만원**을 별도 표시. 첫 달 당월은 **계산 불가**, J의 7월은 정상값 **0.0** |

### E2 — 점검 현장·상황 및 대응 기록·CSV

| 번호 | 사용자가 할 수 있는 일 | 확인할 행동 | 보여야 할 결과 |
|---|---|---|---|
| S06 | 현장별 숫자 비교 | 현장별 비교표에서 9월 전체 확인 후 D 선택 | 전체 **12행**, D 선택 시 **1행·기성률 69.4%**. 지역·유형·당월 주요 공종·금액·공정·상태 표시. 금액은 백만원 |
| S07 | 상황·대응 기록 펼쳐 비교 | D와 I의 기록 펼침을 각각 누르고, 다시 접거나 전체 접기 선택 | 같은 페이지에서 두 기록을 함께 확인. 착공일~계약상 준공일·상황·대응 계획 표시. 전체 접기 후 수치·필터 유지 |
| S08 | 점검 순위에서 기록으로 이동 | 9월 전체 점검 목록에서 D 클릭. 이후 인천·공동주택 선택 | **D → I → K**, 정상 6·주의 3·점검 3곳. D 클릭 시 필터를 유지한 비교표에서 D 행 강조·기록 펼침. 인천·공동주택은 점검 대상 없음 |
| S09 | 선택 범위를 CSV로 내려받기 | 9월 D로 다운로드한 뒤 인천·공동주택으로 다시 다운로드. 각 파일을 가져오기 미리보기에서 확인하고 취소 | 다운로드 실행. 첫 파일은 **D 1행**, 둘째는 **A·G 2행**, 한글 정상 표시. 미리보기 취소 후 기존 자료 유지 |

CSV의 **원본 15개+계산 4개 열, 숫자·단위 보존, 한글 저장 방식**은 개발 담당자가 자동 검사로 함께 확인합니다. CSV 미리보기 확인만으로 실제 엑셀 표시까지 확인했다고 기록하지 않습니다.

### E3 — 근거를 보여주는 AI·로컬 전체 검증

| 번호 | 사용자가 할 수 있는 일 | 확인할 행동 | 보여야 할 결과 |
|---|---|---|---|
| S10 | 점검 이유와 기록된 대응 질문 | D·9월 선택 → AI에게 묻기 → 예시 질문 선택·전송 | 예시는 입력칸에 채워지고 전송 후 답변 생성. **기준 월·D·−10.7pp**, 공급 정상화 후 잔여 지연과 주간 확인 계획을 근거와 함께 설명 |
| S11 | 추이·과거 기록·자료의 한계 질문 | D의 회복 여부, J의 7월 기성 정체 이유, 실제 준공일·미수금을 질문 | D는 **0.5pp 축소하나 점검 유지**. J는 7월 기록에 근거해 서류 보완 설명. 실제 준공일·미수금은 **자료 없음** 안내 |
| S12 | AI 대기·실패 중에도 기본 기능 사용 | 개발 담당자가 준비한 지연·실패 환경에서 전송 후 필터 변경. 실패 후 현황 조회·CSV 다운로드. 대화 초기화 | 이전 답변과 늦게 온 이전 범위 답변은 표시하지 않음. 실패 안내와 별개로 조회·CSV 동작. 초기화해도 자료·필터 유지 |
| S13 | 전체 흐름을 처음부터 재확인 | 새로고침 → 정상 자료 적용 → 필터·추이 → 점검·기록 → CSV → AI 순서로 사용. 인천·생산시설도 선택 | 새로고침 후 자료 없음. 각 화면은 같은 범위·정답 숫자 유지. 인천·생산시설은 **자료 없음·계산 불가**. 화면별 결과와 남은 미확인 항목 보고 |

AI 지연·실패 확인에는 **모의 응답(실제 AI 연결 대신 검사용 응답을 보내는 방식)**임을 표시합니다. 실제 Gemini 호출 검증은 별도로 진행하고, 키가 준비되지 않아 확인하지 못했다면 미확인으로 남깁니다. 실제 호출을 확인하지 않은 상태를 실제 AI 검증 완료로 처리하지 않습니다.

## 공통 구현·검증 기준

| 항목 | 진행 방법 | 이유·근거 |
|---|---|---|
| 구현 순서 | E1 → 사용자 확인 → E2 → 사용자 확인 → E3 → 로컬 전체 검증·결과 보고 | EPIC 하나씩 진행하고 화면 결과를 확인하는 작업 규칙 적용 |
| 기술 준비 | 각 Story 구현에 필요한 실행 환경·공통 화면·자료 관리·계산 함수를 TRD대로 함께 준비 | 기술 준비만 끝난 상태를 사용자 기능 완료로 처리하지 않음 |
| 자동 검사 | 각 Story의 계산·오류 처리를 구현하면서 Vitest(동작과 계산을 자동 확인하는 도구) 검사 작성 | 계산 정확성·오류 처리·자료 보호를 구현에서 빠뜨리지 않음 |
| EPIC별 확인 | 자동 검사와 브라우저 확인 결과를 보고하고 사용자 확인 후 다음 EPIC 진행 | 학습자에게 터미널·코드·개발자 도구 확인을 요구하지 않음 |
| 상세 기능 유지 | 표의 대표 행동 외에도 FRD의 입력 검사·일부 자료·전월 누락·동점 정렬·필터 초기화·답변 초기화·오래된 응답 차단 등을 해당 Story에 포함 | 계획 요약을 이유로 확정된 필수 동작을 빼지 않음 |
| 시안·자료 | 시안의 배치·분위기를 따르고, 현장명·숫자·상황·대응 기록은 원본 사용. data 원본 수정 금지 | 시안의 예시 기록을 실제 근거나 원본 자료로 혼동하지 않도록 함 |
| AI 연결 | TRD의 Gemini `gemini-3.8-flash` 사용. 호출·키 처리는 서버에서만 수행하고 키는 출력하지 않음 | 지정 기술·보안 기준 유지 |
| 실패 조건 준비 | 개발 담당자가 검사용 지연·오류 조건을 준비하고 사용자는 화면에서 전송·필터 변경·조회·다운로드로 확인 | 오류 확인을 위해 학습자가 개발 도구를 조작하지 않도록 함 |
| 실제 AI 확인 | 강사 제공 키가 준비된 환경에서 S10·S11을 실제 호출로 확인. 실패·미실행·모의 응답은 구별 | 실제 연결 검증 여부를 정확히 보고 |
| 최종 로컬 검사 | TRD의 자동 검사·형식 검사·로컬 빌드 후 S13 전체 흐름을 브라우저에서 재확인 | 각 기능의 개별 성공과 전체 흐름의 성공을 함께 확인 |
| 결과 기록 | `docs/05_테스트결과.md`에 자동 검사·사람의 화면 확인·실제 AI·모의 응답·미확인으로 구분해 기록 | 확인하지 못한 것을 확인했다고 말하지 않음 |
| 종료 | 로컬 전체 검증 후 결과·남은 작업을 보고하고 대기. 사용자 확인 전 완료 표시 금지 | GitHub 저장·Vercel 배포를 자동으로 시작하지 않음 |

## 로컬 검증 이후의 별도 단계

아래 단계는 **13개 Story와 구현 완료 조건에 포함하지 않습니다.** 각각 사용자가 별도로 요청한 뒤 진행합니다.

| 단계 | 시작 조건 | 진행 범위 |
|---|---|---|
| GitHub 저장 | 사용자가 저장소 주소를 지정하고 별도로 업로드 요청 | 요청 범위의 비공개 저장소 저장 작업 후 결과 보고·대기. 요청 전 저장소 생성·커밋·푸시 금지 |
| Vercel 배포 | 사용자가 STEP 11에서 직접 진행하거나, 대상 프로젝트·저장소를 정해 AI에게 별도로 요청 | 요청 범위의 프로젝트 생성·연결·환경 변수·배포·확인. 요청 전 실행 금지 |

GitHub 저장 요청은 Vercel 배포 요청을 포함하지 않습니다. GitHub 연동 자동 배포 설정도 별도 요청 전에는 추가하거나 켜지 않습니다. “구현 완료”, “검사 완료”, “확인했어요”, “다음으로”, “알아서 해 주세요”만으로 외부 저장·배포 요청을 받은 것으로 처리하지 않습니다.
